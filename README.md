# LedgerLine

[![CI](https://github.com/Rickygole/LedgerLine/actions/workflows/ci.yml/badge.svg)](https://github.com/Rickygole/LedgerLine/actions/workflows/ci.yml)

Initiative reporting for NYC Council Finance, built for Estrada Consulting for the NYC Council Initiative Reporting System RFP. It is not an official NYC system, and every organization, person and report in it is generated by the seed script.

Live site: https://ledgerline-eosin.vercel.app

Funded organizations file mid-year and year-end reports on the Council funding they receive. Council Finance staff see who is on time, late or missing, review what comes in, request changes, and export the results.

## Who uses it

- **Funded organization:** sees its reports and due dates, fills in a report with a budget grid that must balance to the award, attaches files, certifies and submits, and receives a confirmation email and a PDF copy.
- **Finance analyst:** works from a dashboard of missing, waiting and in-review reports with a Council district map, reviews submissions, flags problems, requests changes, accepts reports, corrects answers with a recorded reason, and exports to Excel or CSV.
- **Finance admin:** everything an analyst does, plus initiatives, report forms, the question library, annual rollover, users and access scopes, and the platform and security controls pages.
- **View-only:** reads the Finance screens and takes no actions.

## Run it locally

You need Node 22, pnpm 10 and Docker.

1. Start Postgres:

   ```
   docker run -d --name ledgerline-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=ledgerline -p 5432:5432 postgres:16
   ```

2. Copy `.env.example` to `.env.local` and fill in `DB_OWNER_URL`, `APP_SERVER_PASSWORD` (24 or more URL-safe characters), `APP_DATABASE_URL` (same password), `AUTH_SECRET`, `GATE_COOKIE_SECRET`, `GATE_PASSCODE` and `PERSONA_PASSWORD`.

3. Install, migrate, enable the app role and seed:

   ```
   pnpm install
   pnpm db:migrate
   pnpm db:role
   pnpm db:seed
   ```

4. Run `pnpm dev`, open http://localhost:3000, enter `GATE_PASSCODE`, then sign in as a seeded user with `PERSONA_PASSWORD`. The sign-in page lists the seeded accounts.

## How it works

Next.js 15 (App Router, server components and server actions), React 19, Tailwind 4 and TypeScript on Postgres 16. The browser never talks to the database.

- **Access is decided in Postgres.** Row level security on every report table filters rows by the user, role and access scope set for the current transaction (`withClaims` in `lib/db.ts`). The app connects as `app_server`, which cannot bypass row level security, read password hashes or write audit rows directly.
- **Status changes go through one function.** `app.transition_submission` checks the action, the role and a lock version, and writes the audit row in the same transaction. A submit is refused unless the budget equals the award and the snapshot matches the saved lines, so even a direct call cannot file an unbalanced report.
- **History is append-only.** Triggers reject UPDATE, DELETE and TRUNCATE on the audit and revision tables. Each submit and correction stores a full snapshot with its SHA-256 hash.
- **Email goes through an outbox.** Messages are written in the same transaction as the action that caused them and delivered through Resend when it is configured. Otherwise they are recorded and shown as Recorded.
- **AI proposes, people decide.** Word form import and the change request note can use a model. Output is validated and logged, and nothing is saved until a person approves it. The hosted site runs without a model, on reviewed saved drafts and rule-based fallbacks, and says so on screen.

## Security

- A shared passcode, then a personal password (bcrypt, at least 12 characters). Failed attempts are throttled in the database, and a session lasts eight hours.
- Reset and invitation links are random, single use and short lived, and only their hash is stored.
- A nonce based Content Security Policy, HSTS and frame blocking on every response.
- Every validation rule is checked again on the server. Uploads are limited to 25 MB and checked by type and content. Exports guard against spreadsheet formula injection.
- `/finance/platform/controls` maps 19 NIST SP 800-53 controls to the code and tests that implement them, and `docs/azure.md` covers the Azure Government target.

## Requirements and tests

`traceability.json` lists the client's 66 user stories (US-nnn) and 29 business rules (BR-nnn). Tests carry the ID in their title, for example `[BR-022]`, and `pnpm evidence` turns the results into `app/trust/evidence.json`, which `/trust` shows to Finance admins. A requirement is Verified when a tagged test passed on its first attempt. Contract commitments such as support, hosting and data ownership are marked Supporting tool built instead.

- **Unit:** rules, formatting, parsers and AI guards.
- **SQL:** row level security, access scopes, the state machine, audit and retention, against a real Postgres.
- **End to end:** Playwright drives each role through the main flows, plus access, accessibility and layout checks.

CI runs migrations, seed, lint, type check, every suite, a build and the evidence script on each push, and deploys `main` to Vercel when they pass.

## Deployment

Vercel with a Postgres database such as Neon. Run `pnpm db:migrate`, `pnpm db:role` and `pnpm db:seed` against the hosted database first.

- Required: `DB_OWNER_URL` (migrations only), `APP_DATABASE_URL`, `APP_SERVER_PASSWORD`, `AUTH_SECRET`, `GATE_COOKIE_SECRET`, `GATE_PASSCODE`, `APP_URL`
- Uploads: `BLOB_READ_WRITE_TOKEN` (otherwise a local `.storage` folder)
- Daily reminders: `CRON_SECRET`
- Email: `RESEND_API_KEY` and `EMAIL_FROM`. With `EMAIL_REDIRECT_TO` set, every message goes to that review inbox instead of its recipient and says who it was intended for.

## Known limits

- Staff sign in with a password and no second factor.
- The production target is a government cloud (Azure Government or AWS GovCloud). This build runs on Vercel and has no compliance review behind it.
- Email is delivered to a review inbox, not to the people named in the data.
- Autosave waits 1.2 seconds after the last edit.

Council district and borough shapes come from NYC Open Data (Department of City Planning, release 26b) under the NYC Open Data Terms of Use, simplified for display only.
